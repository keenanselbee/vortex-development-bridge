0.1.3
- Automatically recovers locks whose owner process has exited, serializing recovery and retaining abandoned lock evidence.
- Waits briefly for active operations and keeps ordinary consumer contention quiet while preserving live or unverifiable owners.
- Cleans up owned locks on normal process exit and dismisses stale error notifications after successful processing.

0.1.2
- Defaults finalization to all profiles for the registered game, with explicit profile targeting retained.
- Updates disabled version selections without enabling or deploying them; absent packages remain absent.
- Keeps enabled-profile work queued until its profile is active and deployment is safe, recording each profile's outcome independently.
- Supports migration from timestamped development versions to newer regular versions and preserves explicit stage-only behavior.
- Adds profile-finish-v3 capability negotiation while retaining existing protocol-1 and protocol-2 requests.

- Adds finalization that stages verified packages and updates enabled versions when the intended profile is active and the game is closed.
- Keeps explicit stage-only finalization available in the page and client without a profile or any activation/deployment side effects.
- Retains offline finalization intents until completed, cancelled or superseded; newer pending updates replace only overlapping package/profile selections.
- Verifies Windows game processes, preserves disabled and newer selected versions, and batches activation into one deployment after preflight.
- Records waiting and partial-effect states without automatically replaying failed or interrupted deployment.
- Requires the updated client and extension for protocol-2 finalization; existing protocol-1 commands keep their expiring behavior. New live acceptance remains pending.
